# 随身常备的当前状态存代码值，不引用动态节点记录

产品设计中"当前状态"可以是动态节点（locations 表 type=virtual 的 @ 节点），但实现里 `items.current_status_tag` 存的是代码值（`carry` / `travel_bag` / `away`）或遗留自由文本，与动态节点记录之间没有外键或名称上的强关联；动态节点管理页展示的"挂载物品"是按节点名与代码值的固定映射推导出来的（@随身↔carry、@通勤包↔travel_bag）。我们决定（2026-09）维持这一口径并文档化，而不是把状态统一为节点引用：统一需要迁移存量数据并同步搜索提示（essentials_hint）与种子数据，改动面大，而当前映射稳定且仅在前端 `features/essentials/shared.ts` 单点维护。

## Considered Options

- **立即统一（current_status_tag 存节点 id）**：数据一致、节点可自定义别名，但需要数据迁移 + 搜索提示/种子数据回归，EDC 场景暂无引用任意自定义节点的需求。
- **维持代码值 + 前端映射（采纳）**：零迁移；代价是"动态节点管理"与物品状态仅有推导式关联，此边界由本文档记录，待节点需要被物品直接引用时再迁移。
