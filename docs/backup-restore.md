# 备份与恢复

Havit 的备份是**整库快照 + 附件打包**，恢复方式为「解包到全新数据目录」。本文档说明备份内容、恢复步骤，以及如何验证恢复可用。

## 备份内容与格式

每次备份产生一个文件：`{数据目录}/backups/{时间戳}_havit.tar.gz`，内含：

- `havit.db`：SQLite 一致性快照（`VACUUM INTO` 生成，备份期间业务可继续读写）
- `attachments/`：全部照片/凭证原图（与 DB 中的附件记录一一对应）

备份文件是自包含的：把整个文件解包到空目录，就是一套完整可启动的数据。

## 触发方式

| 方式 | 说明 |
|---|---|
| 手动 | `POST /api/v1/backups/run`（需登录 Token），返回备份路径与大小 |
| 定时 | `HAVIT_BACKUP_ENABLED=true` + `HAVIT_BACKUP_CRON="0 3 * * *"`（仅支持每日一次），启动后自动调度 |
| 保留策略 | `HAVIT_BACKUP_KEEP_DAYS`（默认由启动参数/环境变量决定），超出天数的旧备份自动清理 |

## 恢复步骤（手动）

恢复 = 把备份解包到全新数据目录，然后正常启动。**Havit 不提供「在线覆盖恢复」**，请按下面流程操作：

1. **停止服务**，确认没有进程占用数据目录（Windows 下任务管理器 / `tasklist`，Linux 下 `systemctl stop havit` 等）。
2. **保留现场**：把当前数据目录改名（如 `data` → `data.bak`），再新建一个空数据目录（路径与原来相同）。
3. **解包备份**到新数据目录：

   ```bash
   tar -xzf backups/2026-09-07T030405_havit.tar.gz -C 新数据目录
   ```

   解包后新数据目录应包含 `havit.db` 与 `attachments/`。
4. **启动服务**：指向新数据目录。启动时会自动执行数据库迁移——备份来自较旧版本时会补齐缺失迁移；来自同版本则无操作。
5. **验证**：登录后抽查关键数据——物品列表、某件物品的照片附件、借出/提醒记录是否齐全。

## 恢复演练验证

自动化的「备份可还原」验证由 Go 测试提供（每次 `go test ./...` 都会跑）：

```bash
go test ./internal/service/ -run TestBackupRestoresIntoFreshDataDir -v
```

该测试执行完整闭环：建库写数据 → 写附件 → `Run()` 生成备份 → 解包到全新临时目录 → 打开恢复后的 DB 并跑迁移 → 断言位置/物品行与附件字节完整。

**已执行的二进制级演练（2026-09-07）**：release 二进制在全新数据目录启动 → `/auth/setup` 创建 Owner → 创建位置、物品（中文名）并上传照片 → API 触发备份 → 停止、清空数据目录 → 解包备份到新目录 → 重新启动 → 登录后中文物品名精确匹配、照片附件字节一致、FTS 搜索可命中。演练结果：通过（记录于 `STATUS.md`）。

## 注意事项

- **demo 模式拒绝在已有数据的目录启动**：`HAVIT_MODE=demo` 遇到非空数据库会直接拒绝启动（防止 demo 误碰真实数据）。因此**恢复演练请在 release 模式下进行**；demo 模式数据是临时的，不需要恢复。
- **同一大版本内恢复**：备份来自更新版本时，旧版本代码可能无法读取新表结构。升级前先备份，恢复时使用与备份相同或更新的版本。
- **目录布局**：恢复后的数据目录必须保持 `havit.db` 在根目录、`attachments/` 与备份时一致，否则附件无法定位。
- **定时备份落盘位置**：备份文件在数据目录内，若数据盘整体损坏，备份也会丢失——建议把 `backups/` 目录同步到另一台机器或网盘。
